# 유튜브판 (2026-11-10 초안)

배포: 스포티파이(오디오북)와 유튜브(영상)에 함께 올린다 → 상업 배포. 쓰는 음원·그림은 모두 상업 이용이 되는 것만.

## 화면 구성 (1920×1080)
- 배경: 장면마다 그림 한 장(Grok 생성). 장면이 바뀌면 1초 교차 전환, 그림은 아주 천천히 확대(정지 화면 느낌 방지).
- 글자: 아래쪽 1/3 반투명 띠에 지금 읽는 조각.
  - 서술(한국어): 문단 그대로. 긴 조각(최대 700자)은 2–3줄씩 넘긴다(글자 수 비율로 시각 나눔).
  - 대사(스페인어): 말한 사람 이름 + 스페인어 + 아래 작은 글씨로 책의 한국어 뜻풀이(`gloss`).
  - 편지: 종이 질감 띠로 바꿔 구분.
- 장 시작: 장 제목 카드("1장 · Hola · 올라") 3초. 장 끝: 간주 음악 동안 다음 장 제목 카드.

## 시간 맞추기 (싱크)
- 조립할 때 조각마다 시작·끝 시각을 적는다(API 안 씀): `audiobook/out/chNN.timeline.json`, `chNN.srt`.
  - 묶음(요청 하나) 사이 경계는 정확하다. 묶음 안 조각 경계는 글자 수로 어림한 뒤 가장 가까운 무음에 맞춘다(오차 대개 0.3초 안).
  - 각 항목: `start, end, scene(장면 번호), kind(title/narr/say/letter/address), who, text, gloss`.
- `scene` 번호가 `video/scenes.tsv`의 장면 번호와 같다 → 그림 바꾸는 시각.
- 1장으로 확인: 95조각, 장면 6개, 시각 역전 없음.
- 낱말 단위 강조(노래방식)가 필요하면 로컬 강제 정렬(whisper 계열)을 따로 붙인다. 지금은 조각 단위.
- `.srt`는 유튜브 자막 파일로 그대로 올릴 수 있다. 유튜브 설명란의 장 타임스탬프도 이 시간표에서 만든다.

## 그림 (Grok)
- `video/style.md`: 공통 화풍 문장, 인물 설정표, 반복 장소 설명.
- `video/scenes.tsv`: 장면 132개마다 프롬프트 한 줄. 넣는 법: 화풍 문장 + 장면 프롬프트 + 등장인물 설정표 문장.
- 인물 일관성: 인물 설정표 그림을 먼저 만들어 참고 이미지로 계속 쓴다. 얼굴은 작게·옆·뒤 위주.
- 파일 이름: `video/img/chNN_sMM.png` (예: ch01_s03.png), 16:9.

## 영상 만들기 (2026-11-10)
도구는 모두 `video/` 아래. 결과는 `video/out/`.

- `render.py N [N…]` → `video/out/chNN.mp4` (1920×1080, 24 fps, H.264).
  - 그림이 없으면 장면 번호·장면 설명을 적은 단색 임시 그림(`video/out/placeholder/`)을 쓴다. 실제 그림을 `video/img/chNN_sMM.png`에 넣고 다시 돌리면 바뀐다.
  - 인코더: ffmpeg(libx264)가 되면 ffmpeg, 아니면 macOS 기본 AVFoundation(`avenc.swift`, 처음에 자동 컴파일, 8 Mbps, 소리는 원본 AAC 그대로). `--encoder ffmpeg|avenc`로 고를 수 있다.
  - 소리: ffmpeg면 AAC 160 kbps 스테레오 48 kHz로 다시 인코딩, avenc면 원본(64 kbps 모노) 그대로.
  - 걸린 시간(1–3장, ffmpeg 9.0.2, 다른 작업과 동시): 장당 3–7분.
  - 1–3장 시험 영상: `video/out/ch01.mp4`–`ch03.mp4`(1920×1080, 24 fps, 길이는 소리와 같음).
  - 시험용: `--from 60 --to 120`(일부만), `--plan`(글자 쪽 시간표), `--check`(ffmpeg 없이 조각마다 프레임 + 모아 본 그림), `--at 12.5`(그 시각 프레임).
- 글자 규칙(코드 맨 위 상수):
  - 서술은 문장 단위로 최대 3줄씩 묶고, 조각 시간을 글자 수 비율로 나눈다.
  - 다음 조각까지 1.2초 안이면 앞 글자를 그대로 두고, 더 비면 끝난 뒤 0.4초에 지운다.
  - 아무리 짧은 조각도 0.8초는 보인다(시간표에 0.01–0.2초짜리 대사가 있어서).
  - 글꼴: 한글은 Apple SD Gothic Neo, 라틴 문자는 Avenir Next. SD Gothic에는 á é í ó ú ñ가 없어서 섞어 그린다. 편지는 AppleMyungjo + Georgia Italic.
  - 화자 이름은 책 본문 표기(윤하, 몬세, 마르크, 발레…). 표는 `render.py`의 `NAMES`.
  - 편지는 종이 띠(마르티 편지면 "마르티의 편지" 표시), 주소·간판(address)은 가운데 정렬.
  - 소리가 시간표 끝보다 4초 넘게 길면(간주) 다음 장 제목 카드를 띄운다. 30장은 "끝" 카드.
- `sync_check.py N` : 시간표 경계를 실제 소리(말 시작점)와 대 본다. 아래 '싱크 점검 결과'.
- `yt_meta.py 1-30 [--book]` → `video/out/meta.json`(업로드 스크립트 형식), `video/out/desc/chNN.txt`(제목+설명 미리 보기).
  - 설명란 타임스탬프 = 장면 시작 시각 + scenes.tsv의 한국어 설명. 유튜브 챕터 규칙(0:00 시작, 3개 이상, 각 10초 이상)에 맞춰 짧은 장면은 합친다.
  - 설명란에 그 장의 스페인어 대사와 뜻(최대 12개), AI 낭독·AI 그림 표기를 넣는다.
  - `--book`: 책 전체를 영상 하나로 올릴 때의 장 타임스탬프(`desc/book_timestamps.txt`).
  - meta.json의 `category`(27 교육), `language`, `contains_synthetic_media`는 참고값이다. 원본 업로드 스크립트는 categoryId 19(여행) 고정이고 합성 표시를 보내지 않으므로, 복사본에서 이 값을 읽도록 고친다.

## 싱크 점검 결과 (1–3장, 2026-11-10)
- 시간표 경계는 대개 쉼이 시작되는 곳이라, 글자가 말보다 0.4–0.7초 먼저 뜬다. 읽기에는 오히려 낫다.
- 장마다 12–14곳은 실제로 어긋난다. 주로 서술 사이에 낀 짧은 스페인어 대사다.
  - 예: 1장 301초. 실제 소리는 "Gracias" 300.1초, "De nada" 301.9–302.5초, 서술 303.6초. 시간표는 "De nada"를 301.40–301.43초(0.03초)에 두고 서술을 301.43초부터 시작한다. 그래서 서술 글자가 약 2초 일찍 뜬다.
  - 같은 꼴: 1장 "¿Agua?" "¿Café?" "Sí." "¡Bon dia!", 3장 "¡Adéu, guapa!" "Ya." 등. 조각 안에 말소리가 거의 없거나, 다음 조각과 같은 말 시작점을 쓴다.
  - 1–2초 일찍 뜨는 곳도 장마다 몇 군데 있다(2장 692초 서술 2.1초, 3장 622초 대사 3.0초).
- 원인은 조립 코드(`audiobook.py`의 `marks`)가 묶음 안 조각 경계를 글자 수로 어림하고 가까운 무음에 맞추는 방식이다. 짧은 대사가 무음 하나를 건너뛰면 뒤 조각이 줄줄이 밀린다. 고치려면 조립 쪽에서 무음 구간을 순서대로 하나씩 배정하거나, 짧은 대사를 따로 자른 길이를 그대로 쓰면 된다. 영상 코드는 시간표를 그대로 따르므로 시간표가 고쳐지면 다시 돌리기만 하면 된다.

## 스포티파이 오디오북 제출 규격 (2026-11-10 확인)
경로는 Spotify for Authors(authors.spotify.com)다. 비독점이고, 게시 후 72시간 안에 나온다.
출처: SFA Metadata & Assets Guide(2024-11 갱신) https://support.spotifycdn.com/pdf/SFA%20Metadata_Asset%20Guide_2024.pdf , https://support.spotify.com/us/authors/article/uploading-audiobooks/

| 항목 | 규정 |
|---|---|
| 형식 | MP3(권장), WAV, FLAC |
| MP3 | 192 kbps 이상, CBR 권장, 44.1 kHz / 16 bit |
| WAV | 44.1 kHz / 16 bit |
| 모노·스테레오 | 둘 다 된다. 한 책 안에서 섞으면 안 된다 |
| 음량 | RMS −24 ~ −14 dB. 피크 상한과 LUFS 기준은 가이드에 없다 |
| 잡음 | −60 dB 미만 |
| 앞 무음 | 0.5–1초 |
| 뒤 무음 | 1–5초 |
| 파일 길이 | 파일 하나에 최대 120분 |
| 장 | 장마다 파일 하나. 시작할 때 장 번호나 제목을 소리로 알린다(지금 "1장. Hola."로 시작함) |
| 여는 크레딧 | 필수. 별도 파일. 제목·저자·낭독자만("…, 지은이 …, 낭독 …") |
| 닫는 크레딧 | 별도 파일. "끝"을 알리는 말 포함 |
| 샘플 | 최대 5분. 음악·크레딧 없이. 없으면 자동 생성 |
| 표지 | 3000×3000 PNG, 1:1 |

- 지금 장 파일(AAC 64 kbps 모노 24 kHz)은 형식·비트레이트·샘플레이트가 모두 맞지 않는다. 원본 PCM에서 44.1 kHz/16 bit WAV나 MP3 192 kbps CBR(모노)로 다시 내보낸다. m4a를 다시 인코딩하지는 않는다.
- 음량: 조립 코드의 말소리 RMS 목표가 약 −18 dBFS라 범위(−24 ~ −14) 안이다. 내보낸 뒤 장마다 RMS와 앞뒤 무음 길이를 확인한다.
- AI 낭독: 받는다. 출처: https://support.spotify.com/us/authors/article/digital-voice-narration/
  - 올릴 때 "This audiobook uses digital voice narration"을 체크한다. 그러면 스포티파이가 설명에 디지털 낭독 문구를 붙인다.
  - 제공사는 "Google Play Books, ElevenLabs 등"으로 예만 든다. 허가된 업체 목록은 없다. Gemini TTS를 금지하는 문구도 없다.
  - AI 낭독 책은 외부 제휴(INaudio → Apple Books·Audible 등)로 내보내지 않는다. 사실상 스포티파이 단독이다.
- 확인 못 함:
  - 한국어 책을 받는지(콘텐츠 언어 목록이 문서에 없음). 업로드 화면의 언어 목록에 Korean이 있는지 직접 봐야 한다. 판매 국가 목록에는 South Korea가 있다.
  - 낭독자 칸에 AI 낭독을 어떻게 적는지. 문서에는 "낭독자가 없으면 출판사 이름" 규정만 있다.
  - 스포티파이 단독 배포에도 ISBN이 필요한지.

## 유튜브 합성 콘텐츠 표시 (2026-11-10 확인)
출처: https://support.google.com/youtube/answer/14328491 , API `status.containsSyntheticMedia`(https://developers.google.com/youtube/v3/docs/videos)
- 표시 의무는 실제처럼 보이는 것에 있다. 실존 인물이 하지 않은 말·행동, 실제 사건·장소를 바꾼 영상, 실제로 없었던 일을 사실처럼 만든 장면, AI 음악이 주된 요소인 경우다.
- 비현실적인 것(동화·애니메이션 같은 그림), 자막 생성, 대본 보조는 표시하지 않아도 된다.
- 이 책: 수채화 그림과 지어낸 이야기, 실존 인물을 흉내 내지 않은 AI 낭독이라 표시 의무 대상이 아닌 쪽이다. 다만 실존하지 않는 사람의 AI 목소리를 다룬 예시는 문서에 없어서 해석이 들어간다.
- 정한 것: 합성 표시는 끄고(`contains_synthetic_media: false`), 설명란에 "낭독: AI 합성 음성, 그림: AI 생성"을 적는다. 켜도 불이익 규정은 없으니 Mike가 원하면 켠다.
- 수익화(YPP) 주의: 2025-07-15부터 '반복 콘텐츠' 규정 이름이 '진정성 없는 콘텐츠'로 바뀌었다. "서사가 거의 없는 그림 슬라이드쇼·흐르는 글자", "대량생산 느낌의 AI 콘텐츠"는 수익화가 안 된다. 출처: https://support.google.com/youtube/answer/1311392
  - 장마다 줄거리가 다른 창작 연재물이라 허용 쪽이지만, 정지 그림 + 글자 + TTS는 겉모습이 겹친다. 장면마다 다른 그림, 설명란의 스페인어 표현 정리처럼 학습용 덧붙임을 유지한다.

## 화면 디자인 시안·HyperFrames 시험 (2026-11-10)
처음 영상(render.py)은 책 디자인을 따르지 않았다(시스템 고딕, 검은 띠, 발음 줄 없음). 책(print.css, build.py)을 기준으로 다시 잡았다.
- 기준: 테라코타 #b5532f, 짙은 초록 #2f5b4a, 크림 #fbf3e6, 먹 #1d1d1b. 고운바탕(한국어), EB Garamond(스페인어·제목), Noto Sans KR(발음). 1부 타일·꽃·열쇠 문양은 build.py의 SVG를 그대로 쓴다.
- 대사마다 책의 한글 발음 줄(강세 굵게, θ 밑줄)과 새 낱말(테라코타)을 build.py에서 읽어 온다(1–6장은 줄 발음이 있음).
- 공통: 제목 카드 = 책 표제지(타일, CAPÍTULO 1, 이탤릭 제목, [발음]). 편지 = 책의 편지 상자(옅은 테라코타 + 왼쪽 선, 이탤릭). 주소 = 책의 초록 상자.
- 서술·대사 방향 세 가지(`video/hf/out/mock_sheet.png`):
  - A 책 한 쪽: 아래 크림색 판에 책처럼 조판. 서술 2줄, 대사는 화자·스페인어·발음·뜻.
  - B 대사 카드: 서술 글자는 띄우지 않는다. 새 낱말이 나올 때 오른쪽 위에 낱말 카드(낱말·발음·뜻, vocab.tsv), 대사는 가운데 크림 카드.
